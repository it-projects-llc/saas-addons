# Русский перевод SaaS Addons 20.0

Для каждого из 23 модулей добавлены `i18n/ru.po` и шаблон
`i18n/<имя_модуля>.pot`. Язык файла — `ru`; код русского языка в Odoo —
`ru_RU`. Odoo автоматически использует этот каталог при установке русского
языка и обновлении соответствующего модуля.

Переведены меню, поля, состояния, подсказки, тарифы, регистрация, личный
кабинет, письма и описания модулей. Термин **Build** переведён как
**Экземпляр**, **Operator** — **Оператор**, **Master** — **управляющий
экземпляр/управляющая база** в зависимости от контекста.

Сообщения Python и JavaScript, которые раньше были жёстко заданы на
английском, помечены через `_()` и `_t()`. Модули `saas_apps` и
`saas_apps_signup` включены в стандартный список словарей переводов
фронтенда. Ключи расчётного периода `month`/`year` в запросах не изменены;
переводится только отображаемый текст.

## Как включить

1. Разместите обновлённые модули в `addons_path` вашего Odoo 20.
2. Перезапустите Odoo, чтобы загрузить изменения Python.
3. В **Настройки → Переводы → Языки** установите/активируйте русский язык.
   Если меню переводов скрыто, включите режим разработчика.
   Если русский уже установлен, обновите установленные модули этого
   репозитория, чтобы загрузить новые переводы. Вручную отдельный каталог
   можно загрузить через импорт переводов с языком **Русский**.
4. Выберите русский язык в параметрах пользователя.
5. В настройках нужного сайта добавьте русский в список языков сайта;
   переключите язык сайта на русский. После обновления модулей перезагрузите
   страницу, чтобы получить актуальные ресурсы JavaScript.

Если необходимо заменить ранее отредактированные переводы, используйте
опцию перезаписи переводов при их импорте. Это отдельное решение:
перезапись может заменить ваши собственные формулировки.

Управляющая база и клиентские базы имеют независимые языковые настройки.
Эти каталоги относятся к модулям данного репозитория. Переводы стандартного
Odoo, OCA contract/queue и клиентских модулей access-addons поставляются
соответствующими проектами.

Названия ваших собственных приложений, пакетов, компаний и экземпляров —
данные, а не строки интерфейса; перевод не переименовывает эти записи.

## Соглашения и OCA

Используется стандартный gettext/Odoo: UTF-8, `Language: ru`, три формы
множественного числа для русского языка, ссылки на исходные строки и
идентификаторы записей Odoo. Параметры `%s`, `{db_name}`, URL, технические
имена и атрибуты HTML/QWeb сохранены. Не добавлены fuzzy-переводы,
сгенерированные `.mo` или отдельный модуль локализации.

[OCA Translation Guidelines](https://github.com/OCA/odoo-community.org/blob/master/website/Contribution/CONTRIBUTING.rst#translations)
требуют выполнять переводы OCA через Weblate, чтобы избежать конфликтов
с ботом. Этот репозиторий принадлежит IT-Projects и не содержит настроек
такой синхронизации; здесь перевод предоставлен локальными каталогами.
При переносе в репозиторий OCA следует использовать его Weblate, а не
отправлять изменения существующих PO-файлов отдельным pull request.

Шаблоны для установленных модулей выгружены средствами Odoo
`20.0-20261015`. В `saas_demo` сохранены проверенные по исходникам термины
из прежнего шаблона, с обновлёнными ссылками для selection/constraint и
без удалённого поля `__last_update`. `saas_demo` и `saas_demo_test`
по-прежнему имеют `installable=False`: наличие перевода не означает
завершения их миграции. Тестовые модули и `host2db` получили каталоги своих
экспортируемых метаданных; их установка для перевода не требуется.

## Проверка

Требуются Python с `polib` и GNU gettext (`msgfmt`). Из корня репозитория:

```sh
uv run --with polib python tools/check_ru_translations.py
```

Проверка охватывает все 23 каталога и 503 запись: совпадение с POT,
заполненность переводов, отсутствие fuzzy/obsolete/дубликатов, заголовки,
подстановки, URL, структуру HTML/QWeb и синтаксис gettext. JavaScript
дополнительно проверяется `node --check`; Python — разбором AST.

Справка по механизму загрузки:
[Odoo: Translating Modules](https://www.odoo.com/documentation/19.0/developer/howtos/translations.html).

Проверка в Odoo 20 выполнена на одноразовой копии управляющей базы:
успешно импортированы каталоги всех 18 установленных модулей и пройдены
16 проверок русских названий и состояний, QWeb тарифов и портала, писем,
исключений Python и словарей JavaScript. Отдельно проверено сохранение
английского значения карточки Builds. Копия удалена; рабочие базы и
их языковые настройки не изменялись.

## Выбор языков нового экземпляра

На форме регистрации поле «Язык администратора» задаёт основной язык
администратора. В новом поле «Языки для установки» можно выбрать несколько
дополнительных языков и найти нужный язык через поиск. Английский и язык
администратора включаются автоматически.

Выбор сохраняется отдельно для каждого экземпляра, включая пробные и
оплачиваемые заказы. Список доступен в карточке экземпляра. Установка
выполняется оператором после создания базы; уже установленные языки не
устанавливаются повторно. Языки разрешается выбирать, даже если они ещё
не активированы в управляющей базе.

После обновления кода требуется обновить модуль `saas_apps_signup` до
версии `20.0.0.2.0`, чтобы создать связь языков с экземплярами и обновить
формы. Проверены 9 регрессионных сценариев, включая HTTP-регистрацию для
пробного и оплачиваемого экземпляра, и реальная установка французского
и немецкого языков в отдельную тестовую базу.
